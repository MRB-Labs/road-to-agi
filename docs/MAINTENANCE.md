# Maintenance guide

This site is a research product, not just a page. Treat it as three systems:
content, visuals and publication.

## Content

- Prose and data live primarily in `assets/content.js`.
- Page slices are generated by `build-content.py`.
- Approved wording lives in `content/copy-snapshot.json`.
- Source governance and evidence ranking live in `method.html` and
  `sources.html`.
- Open sourcing/data gaps live in `TODO.md`.

Rule: do not quietly edit claims. If a figure moves, source it, date it, or
leave the existing as-of qualification.

## Visuals

- Shared site theme: `style.css`.
- Atlas theme and layout: `assets/atlas/`.
- Social preview card: `assets/images/social-card.png`.
- Site icon: `assets/images/favicon.svg`.

Rule: after visual changes, check desktop/mobile and light/dark mode. The
static visual contract guard catches deleted selectors and tokens, but it does
not replace human visual review.

## Publication

- GitHub Actions publish only after guards pass.
- The local editor is excluded from deploy.
- Remote runtime assets are blocked except declared TradingView widgets.
- Asset hashes are part of the publication contract. Run `bump-assets.py`.

## Monthly maintenance

- Check the live canary results.
- Review `TODO.md` for stale data tasks.
- Run `python3 brand/build-companies.py --logos` and decide whether missing
  marks matter.
- Review `assets/market/fundamentals.json` coverage.
- Run `python3 scripts/check-figures.py --list` and date a small batch of
  verified figures.
